# AdapTQ 0.2.2 Release Notes

AdapTQ `0.2.2` is a stabilization release for the `0.2.x` series. This release serves as the frozen stable baseline before we transition to the V2 runtime architecture in the upcoming `0.3.0` release. 

## What Changed

- **Portable AVX2 Capability Detection (Issue #7)**
  Previously, compiling the package embedded `-mavx2` globally into the binaries via `setup.py` and `CMakeLists.txt`. This caused older CPUs without AVX2 extensions to crash with `SIGILL` upon loading the module. 
  - Dynamic `__builtin_cpu_supports("avx2")` dispatching was introduced.
  - The compiler flags `-mavx2` and `-march=native` were removed from Python builds. AVX2 routines are now cleanly sequestered using GCC `#pragma target` attributes, providing universal wheel portability without sacrificing performance on capable processors.

- **Snapshot Storage Validations**
  Metadata boundaries inside `SessionSnapshot::load()` were tightened. Dimensionality (`dim`), bit-widths (`bits`), token limits, and payload allocations are aggressively validated before memory resize events occur to prevent potential buffer misallocations or OOM vectors from corrupted snapshots.

- **Max-Lloyd Codebook Boundary Fortification (Issue #16)**
  Quantizer generation has been validated against zero-variance inputs, infinite precision bursts, and `NaN` cascades. Operations fall back gracefully, avoiding floating-point exceptions and preventing undefined centroid clustering in boundary states.

## Testing & Compatibility

This release is fully backward-compatible with the `0.2.1` API and ABI definitions. 

Native CTest evaluations and complete Pytest validations were enforced prior to this tag. Both execution paths pass successfully against extreme numerical injections.

## Known Limitations

This release does not include Paged KV block layouts, mixed-precision (2/3/4-bit dynamic) allocations, or asynchronous background compression routines. These capabilities form the core of the upcoming `0.2.3` feature set.
