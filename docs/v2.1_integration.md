# AdapTQ V2.1 — Integration Guide

## Overview

AdapTQ V2.1 adds a **backend-agnostic adapter layer** that lets you integrate
AdapTQ's KV cache compression into any LLM inference engine without modifying
the AdapTQ core.

```
Your LLM Runtime
     │
     ▼
IRuntimeAdapter  (thin glue layer)
     │  ← feeds K/V tensors
     ▼
AdapTQ RuntimeContext
  → IKVStrategy  (compress / evict)
  → IStorageBackend (store)
  → IKernelBackend (FWHT + attention)
  → SessionSnapshot (save / replay)
```

## Quick Start

### HuggingFace Transformers (no model file needed)

```python
from adaptq import create_adapter
from adaptq.runtime_py.metadata import ModelConfig

adapter = create_adapter("transformers")
adapter.load_model(ModelConfig(model_path="Qwen/Qwen2-0.5B"))

result = adapter.generate(
    "Explain what a KV cache does in one paragraph:",
    max_new_tokens=80,
)
print(result.text)
print(result.summary())   # includes KV compression stats
```

### llama-cpp-python (requires GGUF model file)

```python
from adaptq import create_adapter
from adaptq.runtime_py.metadata import ModelConfig

# Download: python examples/llama_demo.py --auto-download
adapter = create_adapter("llama_cpp_python")
adapter.load_model(ModelConfig(
    model_path="tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf",
    n_ctx=2048,
    n_threads=4,
    adaptq_bits=4,
))

result = adapter.generate("Hello!", max_new_tokens=50)
print(result.text)
```

### Ollama REST

```python
# Requires: ollama serve && ollama pull tinyllama
from adaptq import create_adapter
from adaptq.runtime_py.metadata import ModelConfig

adapter = create_adapter("ollama")
adapter.load_model(ModelConfig(model_path="tinyllama"))

result = adapter.generate("What is a transformer?", max_new_tokens=60)
print(result.text)
```

## How to Add a New Backend

Follow these steps to create a new `IRuntimeAdapter` subclass.

### 1. Create the adapter file

```
adaptq/runtime_py/backends/my_engine.py
```

### 2. Implement the interface

```python
from adaptq.runtime_py.base import IRuntimeAdapter
from adaptq.runtime_py.metadata import (
    GenerationResult, KVStats, ModelConfig, RuntimeMetadata, SessionConfig
)

class MyEngineAdapter(IRuntimeAdapter):
    BACKEND_NAME = "my_engine"

    def __init__(self):
        # Check that required packages are installed
        try:
            import my_engine_package  # noqa
        except ImportError:
            raise ImportError("my_engine backend requires: pip install my-engine")
        self._meta = RuntimeMetadata(backend_name=self.BACKEND_NAME)
        self._error = ""

    def load_model(self, cfg: ModelConfig) -> bool:
        try:
            # Load your model here
            self._model = MyEngine(cfg.model_path)
            # Populate metadata
            self._meta.n_layers = self._model.n_layers
            self._meta.n_heads  = self._model.n_heads
            self._meta.head_dim = self._model.head_dim
            self._meta.kv_access = True   # or False if no KV hook
            return True
        except Exception as e:
            self._error = str(e)
            return False

    def load_tokenizer(self, path: str) -> bool:
        return True  # If tokenizer is bundled with the model

    def begin_session(self, cfg: SessionConfig) -> bool:
        self._session_cfg = cfg
        return True

    def end_session(self) -> bool:
        return True

    def tokenize(self, text: str) -> list[int]:
        return self._model.tokenize(text)

    def detokenize(self, token_ids: list[int]) -> str:
        return self._model.detokenize(token_ids)

    def prefill(self, tokens: list[int]) -> bool:
        try:
            self._model.eval(tokens)    # or however your engine prefills
            return True
        except Exception as e:
            self._error = str(e)
            return False

    def decode_next(self) -> int | None:
        try:
            tok = self._model.sample()
            if tok == self._model.eos_token_id:
                return None
            self._model.eval([tok])    # feed back for next step
            return tok
        except Exception as e:
            self._error = str(e)
            return None

    def get_kv_stats(self) -> KVStats:
        # Return real KV stats if your engine exposes them,
        # otherwise return estimated stats.
        return KVStats(
            kv_bytes_adaptq=self._model.kv_bytes,
            kv_bytes_fp16=self._model.n_tokens * self._meta.n_heads * self._meta.head_dim * 2 * 2,
        )

    def clear_kv_cache(self) -> bool:
        self._model.reset()
        return True

    def metadata(self) -> RuntimeMetadata:
        return self._meta

    def last_error(self) -> str:
        return self._error

    def generation_result(self) -> GenerationResult:
        return GenerationResult()  # populated in end_session() if needed
```

### 3. Register the backend

Edit `adaptq/runtime_py/backends/__init__.py`:

```python
_REGISTRY: Dict[str, str] = {
    ...
    "my_engine": "adaptq.runtime_py.backends.my_engine.MyEngineAdapter",
}
```

### 4. Add tests

Create `integration_tests/test_my_engine.py` following the pattern in
[test_transformers.py](../integration_tests/test_transformers.py).

### 5. Done

```python
from adaptq import create_adapter
adapter = create_adapter("my_engine")
adapter.load_model(ModelConfig(model_path="..."))
result = adapter.generate("Hello!")
```

## KV Interception Strategies

### Strategy A: Cache subclass (transformers pattern)

Override the cache class's `update()` method. This is the cleanest
approach when the engine uses a Python-accessible cache abstraction.

```python
class AdapTQCache(DynamicCache):          # transformers
    def update(self, key_states, value_states, layer_idx, ...):
        # Feed through AdapTQ
        self._adaptq_engines[layer_idx].append(k_np, v_np)
        return super().update(...)        # keep model's own KV too
```

### Strategy B: Eval loop intercept (llama-cpp-python pattern)

Hook into the token generation loop and read K/V after each step.

```python
def decode_next(self) -> int | None:
    tok = self._model.sample()
    self._model.eval([tok])
    # Read K/V state from model internals
    k = self._model.get_last_k()  # engine-specific
    v = self._model.get_last_v()
    self._adaptq_engine.append(k, v)
    return tok
```

### Strategy C: C++ patch (llama.cpp direct pattern)

Modify the inference engine's C++ code to call `adaptq_mha_append()`
after computing K and V tensors. See [llama_cpp_patch.md](llama_cpp_patch.md).

### Strategy D: REST only (Ollama pattern)

When no KV state is accessible (REST API only), capture generation
metrics and text only. Mark `kv_access = False` in RuntimeMetadata.

## Snapshot + Replay with Adapters

After generating tokens via an adapter, use the AdapTQ CLI or Python API
to capture, save, and replay snapshots:

```bash
# Generate and save snapshot via the Python adapter
python examples/transformers_demo.py

# Replay the snapshot with the AdapTQ CLI
./build_v2/adapTQ_demo replay session.aqss --metrics

# Compare strategies on the same snapshot
./build_v2/adapTQ_demo compare session.aqss \
    --strategies har_fixed,fp_passthrough --format md
```

## Troubleshooting

**`ModuleNotFoundError: No module named 'adaptq.runtime_py'`**
→ Run `pip install -e .` from the adapTQ directory.

**`KV stats all zero`**
→ Install the C++ Python binding: `pip install -e .` (builds `adaptq_py.so`).

**`transformers backend not available`**
→ `pip install transformers accelerate torch`

**`llama_cpp_python: model file not found`**
→ `python examples/llama_demo.py --auto-download` (downloads TinyLlama ~700MB)

**`ollama: connection refused`**
→ Start the server: `ollama serve &` then `ollama pull tinyllama`
